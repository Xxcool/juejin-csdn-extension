# 摆渡链路与状态机剖析 (Pipeline Architecture)

深入了解「文章摆渡」的内部处理管线，有助于更好地理解其在面对复杂网络环境、高并发图床请求以及跨平台限制时的稳定性表现。

如上图所示，一次完整的摆渡包含以下核心阶段：

### 1. 触发与快照捕获 (Trigger & Capture)
- **事件拦截**：在掘金发文面板点击“确定并发布”时，由 Content Script 拦截发文事件；
- **元数据打包**：抽取文章标题、正文 Markdown、封面图 URL、掘金摘要及分类；
- **消息派发**：通过 `chrome.runtime.sendMessage` 将轻量级任务对象派发至后台 Service Worker。

### 2. 预演与准备 (Dry-run & Preparation)
- **连通性校验**：向 CSDN 会话检测端点发送心跳探针，确认用户处于有效在线态；
- **分类专栏拉取**：查询创作者个人的 CSDN 专栏列表，若用户未指定分类，智能匹配默认专栏；
- **排版合规分析**：分析正文中的特有容器、无闭合代码围栏及外部图片。

### 3. 内容与图床加工 (Cleanse & Image Transfer)
- **语法转译**：清洗掘金特有容器（`:::tips` 等）为标准 Markdown 引用块；
- **原创声明注入**：在正文尾部注入首发声明；
- **无水印直链提取**：剔除 CDN 裁剪水印参数；
- **三路并发上传**：将图片流式推送到 CSDN 图床，获得新的图片访问地址并原地回填替换 Markdown。

### 4. 幂等保存与自愈 (Save & Auto-Healing)
- **检查映射**：查询该文章在本地是否已有对应的 `draft_id`；
- **线上状态巡检**：若为更新模式，预先校验该博文是否已在 CSDN 正式上线（若已发布则阻断并提示）；
- **执行提交**：提交草稿数据至 CSDN 接口；
- **400 自愈分支**：若服务端返回“文章不存在”，自动降级为新建模式，更新本地映射表；
- **通知派发**：若总耗时超过阈值或包含多图，向系统通知中心播报成功状态。

## ⚙️ Chrome MV3 架构与 DNR 网络规则


在 Chrome Manifest V3 体系下，传统的后台页面（Background Page）被无状态的 **Service Worker** 取代。Service Worker 会在空闲时被浏览器随时休眠挂起。

文章摆渡通过以下技术保证链路可靠：
1. **状态持久化驱动**：所有任务状态与执行断点实时同步至 `chrome.storage.local`，唤醒时自动恢复未决状态；
2. **DNR 严格限制 (Declarative Net Request)**：
   - 传统插件常使用宽泛的 `webRequest` 权限，存在安全审计风险；
   - 文章摆渡采用 `rules.json` 显式静态规则，**仅对特定官方接口定向补充合规请求头（如 Referer / Origin）**，权限最小化。
