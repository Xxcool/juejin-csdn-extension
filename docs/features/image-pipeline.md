# 原图转存与语法清洗 (Image Pipeline)

在不同平台之间迁移技术博文时，最常见的痛点莫过于：**图片带水印导致目标平台审核不通过**、**图片二次压缩变模糊**以及**平台专属 Markdown 扩展语法在第三方平台变成一堆乱码**。

文章摆渡通过专门的图片转存管线与语法清洗器，系统性解决了上述问题。

## 🖼️ 无水印原图直链提取算法

掘金平台为了防盗链与加速，在图片 URL 中常追加大量模板参数与 OSS 处理规则，例如：

```text
https://p3-juejin.byteimg.com/tos-cn-i-k3u1fbpfcp/xxx~tplv-k3u1fbpfcp-zoom-in-crop-mark:1304:0:0:0.awebp?x-oss-process=image/watermark...
```

如果直接原样转存，会将缩放裁剪甚至平台专属水印一同固化在 CSDN 的草稿中。

### 提取与清洗逻辑
1. **剔除模板标识**：匹配并移除 `~tplv-` 开头的图片变换段，还原资源原始唯一标识；
2. **剔除裁剪水印参数**：清除 Query 参数中的 `x-oss-process`、`imageView2`、`watermark` 等参数；
3. **直链试探与降级回退**：
   - 优先拉取无水印纯净原图直链；
   - 若原图直链因平台防盗链规则返回 404，算法将**自动静默回退至带参数的原始 URL**，确保绝不因为单张图片的参数裁剪导致整篇文章同步失败。

## 🚀 三路有限并发与指数退避重试

在处理包含数十甚至上百张架构图、流程图的大体量技术长文时，如果暴力发起全量并发下载与上传，极易导致：
- 触发目标图床服务的防刷限制（HTTP 429）；
- 耗尽浏览器客户端网络连接池。

### 调度策略
- **有限并发**：严格采用最大 3 路的 Worker 并发池（`Promise.all` + 信号量分片）；
- **指数退避重试**：遇到瞬时网络抖动或服务端 5xx 时，依次延迟 1s、2s、4s 进行最多 3 次重试；
- **防盗链外链兜底**：若某张图片经过多次重试依然下载失败，系统将**保留原始外链**并在诊断日志中标记警告，而不是暴力中断整篇博文的同步。

## 📝 专属容器语法转译为标准 Markdown


掘金编辑器支持诸如 `:::tips`、`:::note`、`:::warning` 等特定扩展容器语法。在没有做语法清洗前，这些语法在 CSDN 编辑器中会被直接渲染成未解析的普通字符串：

```markdown
:::tips
这是一个提示内容
:::
```

文章摆渡在同步前自动将其转译为通用 Markdown 规范支持的标准引用块：

```markdown
> 💡 **提示**：
> 这是一个提示内容
```

这不仅使排版在 CSDN 编辑器中自然优雅，还保持了跨平台的排版语义一致性。
