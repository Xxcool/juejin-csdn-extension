# 智能同步引擎 (Sync Engine)

文章摆渡的同步引擎是基于 Chrome Manifest V3 的后台 Service Worker 与 Declarative Net Request (DNR) 机制设计的高性能、非阻塞调度核心。

## ⚡ 双路径文章快照提取

为了确保长文以及历史旧文的原始 Markdown 语法丝毫不失真，同步引擎实现了创新的**双路径快照按需拉取机制**：

```
                    ┌─── 1. 发文时即时捕获 (发布面板拦截) ───┐
                    │                                      ▼
[创作者触发同步] ────┤                               [写入轻量任务元数据]
                    │                                      ▲
                    └─── 2. 历史迁移反查草稿 (Draft API) ─────┘
```

### 1. 发文即时捕获（新博文发文场景）
当创作者在掘金编辑界面点击“发布”并勾选同步时：
- Content Script 拦截发布动作，直接读取编辑器内存中的实时 Markdown 原文；
- 同步提取已选分类、标签列表与作者手填摘要；
- 发起异步摆渡任务后立即放行掘金原生发文事件，**完全不阻塞掘金界面的后续审核或提示弹窗**。

### 2. 历史文章反查草稿（历史迁移场景）
对于已在掘金公开发布的存量文章，公开接口通常只提供经过编译渲染后的 HTML，直接反编译会导致代码缩进丢失或语法畸变。  
文章摆渡采用 **Draft 反查机制**：
- 通过 `article/list_by_user` 接口获取博文对应的 `draft_id`；
- 紧接着请求 `article_draft/detail` 获取第一手原始未编译的纯正 Markdown 代码；
- 从而保证了代码高亮、公式与表格原汁原味落地。

## 🚦 全局串行限速任务队列

为了防止多任务并发冲击导致目标平台触发反爬风控或 `429 Too Many Requests`，引擎内置了自适应限速调度队列：

- **单篇流式执行**：同一时刻仅允许 1 篇博文进入实质搬运状态，多篇批量迁移按 FIFO 顺序排队执行；
- **并发细粒度隔离**：正文内的图片转存严格限制在 3 路并发；
- **心跳守护与故障自愈**：若遇 Chrome 浏览器切后台休眠，引擎会在唤醒后无缝恢复中断的管道步骤，避免卡死在半途。

## 📋 任务状态机定义


每个任务在生命周期中经历明确的状态迁移：

| 状态标识 | 说明 | 对应 UI 表现 |
| :--- | :--- | :--- |
| `pending` | 等待进入调度队列 | 浅灰色等待徽章 |
| `running` | 正在提取、清洗或上传 | 蓝色穿梭流光动画 + 实时进度文字 |
| `saved` | 成功落盘 CSDN 草稿箱 | 翠绿勾选徽章 + 蓝光高亮「草稿 ↗」按钮 |
| `failed` | 执行中发生不可抗错误 | 红色警示徽章 + 细分错误原因标签 |
| `cancelled` | 用户主动取消 | 灰度取消标识 |
