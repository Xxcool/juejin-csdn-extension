# 常见问题与排错自查 (FAQ)

本文汇总了使用「文章摆渡」过程中的常见疑问与故障排查方案。

## 登录与状态类

### Q1: 扩展弹窗顶部显示“CSDN 未登录”？
**原因**：文章摆渡通过调用 CSDN 会话检测接口判断在线状态。若您在浏览器中未登录 CSDN、或登录态已过期，会显示未登录。  
**解决办法**：
1. 点击顶部状态胶囊或直接在浏览器新标签页访问 [CSDN 首页](https://www.csdn.net) 并登录；
2. 登录成功后，切回扩展弹窗，点击状态胶囊旁的刷新按钮即可立即识别。

### Q2: 为什么不需要在插件里输入账号和密码？
**解答**：文章摆渡秉持 **100% 本地端侧安全与零信任原则**，绝不索取、存储或中转用户的账号与密码。插件直接借助浏览器原生的 Cookie 会话通道与 CSDN API 通信，确保最高级别的隐私与资产安全。

## 同步与草稿类

### Q3: 如果我把 CSDN 草稿箱里的旧草稿删除了，再次同步会卡死吗？
**解答**：**绝不卡死，系统具备自动降级自愈能力。**  
在 v0.6.0 之前，若目标草稿被手动删除，更新请求会返回 400 报错；v0.6.0 引入了 **400 删稿自愈引擎**：
- 当识别到目标草稿不存在时，系统自动降级为新建模式；
- 新生成的 `draft_id` 会原地覆盖旧映射；
- **自愈过程复用已转存的图片**，无需重复上传，秒级完成自我修复。

### Q4: 再次同步会覆盖我已经公开发布的 CSDN 博文吗？
**解答**：**绝不会！这是系统的底线安全红线。**  
在向 CSDN 提交写入之前，扩展会拉取目标文章的当前线上状态：
- 若检测到该文章在 CSDN 已经处于 **“已公开发布”** 状态，系统将**强制阻断更新覆盖操作**；
- 界面将提示风险并引导用户转为新建独立草稿，彻底杜绝意外损坏已发布内容或破坏线上评论点赞数据的悲剧。

## 图片与排版类

### Q5: 掘金文章里的图片转存到 CSDN 会变模糊或带水印吗？
**解答**：不会。  
文章摆渡在解析图片 URL 时，会自动识别并剔除掘金 CDN 的模板缩放参数（如 `~tplv-...`）以及 OSS 裁剪水印参数（如 `x-oss-process=image/watermark...`），优先拉取原始无损高清大图转存至 CSDN，保障图片细节纤毫毕现。

### Q6: 为什么文章末尾多了一行“本文首发于掘金”？
**解答**：  
这是文章摆渡为了保护创作者多平台分发时的 SEO 权重与原创版权而设计的特性。默认在正文末尾追加引用声明，避免因平台抓取顺序问题被搜索引擎判定为重复采集站。  
*如果您不需要此声明，可在扩展弹窗的「偏好设置」面板中随时关闭该开关。*

## 异常与诊断类


### Q7: 遇到任务失败，如何快速排查？
1. 在扩展弹窗的「同步记录」中找到失败的任务卡片；
2. 卡片会以高亮标签直接标明错误类型（如 `网络异常`、`会话失效`、`图片防盗链`、`接口限流` 等）；
3. 点击卡片底部的 **“复制脱敏诊断信息”**；
4. 诊断信息已自动抹去个人敏感数据，仅保留错误阶段、接口响应码与堆栈，您可以将此信息提交至 [GitHub Issues](https://github.com/Xxcool/juejin-csdn-extension/issues) 寻求开发者协助。
